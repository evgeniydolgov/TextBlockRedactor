# Критерии готовности

Применяйте только проверки, относящиеся к изменению. Неприменимые пункты отмечайте N/A с причиной.

## Для любой задачи

- [ ] Результат соответствует запросу; лишние функции и зависимости не добавлены.
- [ ] Сохранены чужие изменения; diff содержит только относящиеся к задаче файлы.
- [ ] Документы и относительные ссылки актуальны.
- [ ] В отчёте отделены выполненные проверки от непроверенных предположений.
- [ ] Агент не создавал коммиты, не выполнял amend и не переписывал историю.
- [ ] Агент не выполнял git add или другие операции изменения индекса;
      уже подготовленные пользователем файлы сохранены в индексе.
- [ ] При изменениях файлов предложено название коммита; при отсутствии изменений
      название не предлагается. Создание коммита оставлено пользователю без запроса
      разрешения сделать это за него, в том числе после OpenSpec apply/archive.

## Для OpenSpec и документации

- [ ] `npm.cmd run spec:validate` проходит.
- [ ] Спецификации описывают текущее поведение, proposals — будущие изменения.
- [ ] Команды инструкции доступны в установленной версии CLI.
- [ ] `git diff --check` не находит ошибок пробелов.

## Для кода и конфигурации приложения

- [ ] `npm.cmd run build` проходит.
- [ ] `npm.cmd run lint` проходит.
- [ ] При изменении нашей логики `npm.cmd test` проходит; существенные ветви
      проверены unit-тестами без Tiptap runtime, UI и браузера. При изменении
      тестов или покрываемых функций выполнен `npm.cmd run test:coverage`;
      процент относится только к модулям, указанным в vitest.config.ts.
- [ ] Проверены изменённые операции и существенные граничные случаи.
- [ ] Изменённый CSS содержит одну декларацию на строку с отступом 2 пробела;
      пустые строки разделяют правила, а не каждую пару деклараций.
- [ ] Браузерные проверки выполнялись только по прямому запросу пользователя.
      Без такого запроса UI-сценарии переданы для ручной проверки и в отчёте указано
      «не выполнялось по правилу проекта». Отсутствие этой проверки само по себе
      не блокирует завершение задачи; HTTP 200 и build не считаются UI-тестом.

## Регрессия редактора при изменениях его поведения

Это список для ручной проверки пользователем. Агент выполняет его в браузере
только по прямому запросу; без запроса пункты не отмечаются как пройденные.
Не запускайте автоматически headless, вкладки, скриншоты, браузерные стенды
или dev-команды с auto-open и не запрашивайте разрешение при каждой задаче.

- [ ] Ввод русского текста, удаление Backspace/Delete и Enter работают.
- [ ] Текст переключается в H1/H2/H3 и обратно без потери содержимого.
- [ ] Undo/redo работают для редактирования.
- [ ] Пустой документ остаётся доступным для ввода.
- [ ] Панель доступна с клавиатуры; активный тип блока соответствует позиции курсора.
- [ ] До отдельной задачи о сохранении обновление страницы сбрасывает черновик,
      а интерфейс сообщает, что изменения не сохраняются.
