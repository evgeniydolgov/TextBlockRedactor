# Критерии готовности

Применяйте минимальный достаточный набор проверок непосредственно затронутой области.
Неприменимые пункты отмечайте N/A с причиной. Политика scope и контекста — в
[AGENTS.md](../../AGENTS.md). Не добавляйте проверки «на всякий случай».

## Для любой задачи

- [ ] Результат соответствует запросу; лишние функции и зависимости не добавлены.
- [ ] Scope и acceptance текущего change соблюдены; посторонние проблемы лишь
      кратко зафиксированы, не исследованы и не исправлены без разрешения.
- [ ] Использован необходимый контекст без повторного чтения уже изученного;
      при существенном росте объёма исследования работа остановлена до ответа пользователя.
- [ ] Сохранены чужие изменения; diff содержит только относящиеся к задаче файлы.
- [ ] Документы и относительные ссылки актуальны.
- [ ] В отчёте отделены выполненные проверки от непроверенных предположений.
- [ ] Агент не создавал коммиты, не выполнял amend и не переписывал историю.
- [ ] Агент не выполнял git add или другие операции изменения индекса;
      уже подготовленные пользователем файлы сохранены в индексе.
- [ ] При изменениях файлов предложено название коммита; при отсутствии изменений
      название не предлагается. Создание коммита оставлено пользователю без запроса
      разрешения сделать это за него, в том числе после OpenSpec apply/archive.

## Для OpenSpec и документации

- [ ] Прочитаны изменённые разделы и только их diff; локальные ссылки корректны.
- [ ] Спецификации описывают текущее поведение, proposals — будущие изменения.
- [ ] Команды инструкции доступны в установленной версии CLI.
- [ ] Ради Markdown не запускались проверки кода. Без разрешения full gate
      не запускались OpenSpec validation и diff-check.

## Для кода и конфигурации приложения

- [ ] Новая/изменённая логика покрыта локальными unit-тестами без Tiptap runtime и UI;
      запущены только соответствующие test-файлы, их команды и результаты указаны.
- [ ] Выполнен минимальный type-check затронутого кода, если он возможен штатными
      средствами; иначе ограничение отмечено без запуска полного tsc/build.
- [ ] Проверены только операции и граничные случаи, необходимые для текущей спецификации.
- [ ] После достаточных локальных проверок работа завершена без расширения проверки.
- [ ] Изменённый CSS содержит одну декларацию на строку с отступом 2 пробела;
      пустые строки разделяют правила, а не каждую пару деклараций.
- [ ] Браузерные проверки выполнялись только по прямому запросу пользователя.
      Без такого запроса UI-сценарии переданы для ручной проверки и в отчёте указано
      «не выполнялось по правилу проекта». Отсутствие этой проверки само по себе
      не блокирует завершение задачи; HTTP 200 и build не считаются UI-тестом.

## Full Quality Gate — только по явной команде

Этот раздел применяется только после команды пользователя, например
`Run full quality gate`. До неё полный gate запрещён и не является критерием
готовности обычной задачи. Propose/apply/archive не разрешают его автоматически.
Не запрашивайте gate при каждом завершении работы.

- [ ] Все unit-тесты: `npm.cmd test`.
- [ ] Глобальный coverage: `npm.cmd run test:coverage`.
- [ ] Полный lint: `npm.cmd run lint`.
- [ ] Полный type-check и production build: `npm.cmd run build` (включает `tsc -b`).
- [ ] OpenSpec validation: `npm.cmd run spec:validate`.
- [ ] Проверка пробелов: `git diff --check`.
- [ ] Другие глобальные проверки — только если предусмотрены проектом и запросом.

Отчёт указывает фактические результаты, без автоматического исправления посторонних
проблем. Браузерные/E2E/визуальные проверки требуют отдельного прямого запроса.

## Регрессия редактора при изменениях его поведения

Это список для ручной проверки пользователем. Агент выполняет его в браузере
только по прямому запросу; без запроса пункты не отмечаются как пройденные.
Не запускайте автоматически headless, вкладки, скриншоты, браузерные стенды
или dev-команды с auto-open и не запрашивайте разрешение при каждой задаче.

- [ ] Ввод русского текста, удаление Backspace/Delete и Enter работают.
- [ ] Текст переключается в H1/H2/H3 и обратно без потери содержимого.
- [ ] Undo/redo работают для редактирования.
- [ ] Пустой документ остаётся доступным для ввода.
- [ ] Панель доступна с клавиатуры; активный тип блока соответствует позиции курсора.
- [ ] Во время ввода сохранение ожидает паузу saveDelayMs (по умолчанию 1000 мс),
      после паузы записывается последнее состояние, при уходе — сразу.
- [ ] После перезагрузки заметка восстанавливается из localStorage с прежними ID;
      удалённый текст не возвращается, ошибки storage не ломают редактирование.
