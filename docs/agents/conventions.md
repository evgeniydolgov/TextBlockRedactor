# Соглашения

## Реализация

- TypeScript, функциональные React-компоненты, обычный CSS.
- Сохраняйте стиль существующего кода: 2 пробела, одинарные кавычки, без точек с запятой.
- Компоненты — PascalCase, функции и переменные — camelCase.
- Один экземпляр Tiptap на документ. Не дублируйте его содержимое в React state.
- Расширения подключайте в src/editor/extensions.ts; UI редактора — в src/editor/.
- initialContent — только начальное значение; onChange передаёт JSON.
- Не добавляйте зависимости без конкретной необходимости. Для новых пакетов проверьте
  лицензию и совместимость; сохраняйте package-lock.json вместе с package.json.
- Пользовательские подписи — по-русски; сохраняйте доступные подписи и управление с клавиатуры.

## Документы

- UTF-8; в Windows PowerShell читайте русский текст через Get-Content -Encoding UTF8.
- Короткие инструкции, относительные ссылки, проверенные команды.
- Новые требования описывайте наблюдаемым поведением и сценариями WHEN/THEN.
- Не выдавайте планы за реализованные возможности.
- Не переносите технические инструкции в интерфейс продукта.

## Проверки и Git

- В PowerShell используйте npm.cmd: npm.ps1 может блокироваться политикой выполнения.
- Не запускайте второй Vite для той же папки. Адрес проекта: http://127.0.0.1:3000.
- Не завершайте неизвестный процесс ради освобождения порта.
- Тестируйте изменённое поведение. Не добавляйте тестовый фреймворк ради правки Markdown.
- Один логический результат — один коммит. Формат: type(scope): конкретное действие.
  Примеры: docs(agents): document task workflow; chore(openspec): initialize project specs.
- Добавляйте в индекс только относящиеся к задаче файлы. Не используйте git add . без проверки.
- Не переписывайте историю и не отправляйте изменения в remote без запроса пользователя.
