# Блоки заметки

`TextEditor` принимает `initialContent?: NoteDocument` и
`onChange?: (blocks: NoteDocument) => void`, `saveDelayMs?: number`.
NoteDocument — массив полных блоков;
внутренний Tiptap JSON не является публичным форматом. Без initialContent или с []
создается один пустой paragraph с уникальным ID. Изменение initialContent после
создания редактора не загружает другой документ.

Пропсы `maxBlockCharacters=8000`, `maxNoteCharacters=50000`, `maxBlocks=100`
ограничивают текст и число блоков, включая пустые. Считается `.length` объединённых
строк text; `😀` занимает 2 единицы. Переполнение продолжается в новых paragraph,
первый фрагмент сохраняет тип/ID. Загрузка и снижение лимитов обрезают хвост
до отображения. [Подробные правила, история и ручная проверка](content-limits.md).

## Поддерживаемый формат

Форма соответствует [BlockNote](https://www.blocknotejs.org/docs/foundations/document-structure)
для текущего подмножества: paragraph и heading уровней 1–3, обычный текст.
Значения общих props: backgroundColor/textColor = "default", textAlignment = "left".
У heading дополнительно level и isToggleable: false.

```json
[
  {
    "id": "a",
    "type": "paragraph",
    "props": {
      "backgroundColor": "default",
      "textColor": "default",
      "textAlignment": "left"
    },
    "content": [{ "type": "text", "text": "Привет", "styles": {} }],
    "children": []
  }
]
```

Пустой текст представлен content: []. Соседние текстовые сегменты объединяются
без удаления пробелов; границы блоков и Unicode сохраняются. children пока всегда [].
Старый doc/attrs JSON, частичные блоки, дубли/отсутствие ID, ссылки, непустые styles,
вложенность, другие типы и значения props отклоняются с ошибкой поля/индекса.
Это не импорт всех возможностей BlockNote. Проверенные формы:
[общие props](https://www.blocknotejs.org/docs/features/blocks),
[paragraph/heading](https://www.blocknotejs.org/docs/features/blocks/typography).

## Идентификаторы

ID хранится в узле документа, не создается заново при экспорте.
Все новые ID создаются общим генератором UUID v7: при создании пустой заметки,
разделении блока и назначении ID через UniqueID, включая вставку копии.
Существующие ID из initialContent принимаются без проверки версии UUID:
например, UUID v4 или строка "123" сохраняются при редактировании и экспорте.
Проверки непустой строки и точных дубликатов остаются. Миграции и автоматической
замены существующих ID нет; документ может содержать старые ID и новые UUID v7.
Обычный ввод, смена типа и уровня сохраняют ID. При Enter первый фрагмент всегда
сохраняет ID, даже если курсор был в начале и первый фрагмент пустой; второй
получает новый ID. Удаленные блоки исчезают без перенумерации остальных.

UniqueID 3.31.3 (MIT) обеспечивает ID для вставок и обработку дубликатов;
его generateID подключен к общему генератору на uuid 14.0.2 (MIT).
Проверка его исходного кода показала перенос ID вправо при пустом левом фрагменте;
наш splitBlock-адаптер задает разные ID до запуска плагина и сохраняет выбранное правило.
Адаптеры setNode/clearNodes сохраняют ID каждого выделенного блока в той же
транзакции. Heading input rule переносит ID при вводе #/##/###.
Весь split вместе с назначением ID входит в одну операцию истории.

## Автосохранение

`saveDelayMs` задаёт паузу перед onChange в миллисекундах, по умолчанию 1000.
Каждое изменение перезапускает ожидание; ввод отображается сразу. `0` вызывает
onChange без ожидания. Отрицательные, не конечные значения и значения больше
2147483647 заменяются на 1000. Изменение пропса перезапускает текущее ожидание
с новой задержкой; обычный рендер и замена callback его не сдвигают.
Удаление callback отменяет ожидающую передачу. Mount не отправляет документ.

На странице настройка вынесена в `NOTE_SAVE_DELAY_MS` в DocumentPage.tsx.
Страница сохраняет NoteDocument в localStorage под ключом `text-block-redactor:note:v1`
и загружает его перед созданием редактора. ID сохраняются без проверки версии UUID.
Удаление всего текста сохраняет пустую заметку. История undo/redo не сохраняется.

При hidden/pagehide и размонтировании ожидающий снимок передаётся сразу; повторные
события не дублируют передачу. При принудительном завершении браузера без событий
несохранённый ввод может потеряться. Хранилище привязано к origin (адресу и порту);
несколько вкладок пишут одну запись, побеждает последняя успешная запись.

Если записи нет, редактор пустой. При повреждённом JSON, неподдерживаемом формате
или ошибке чтения открывается пустой редактор с сообщением; исходная запись
не удаляется и не перезаписывается до редактирования. Ошибка записи показывается
под редактором и не теряет текущий текст; следующее редактирование повторяет попытку.
Успешная запись убирает сообщение об ошибке. Сам TextEditor не обращается к storage.

## Просмотр в консоли и ручная проверка

Дополнительно страница показывает `[note:requests]` и записывает последний цикл
в `text-block-redactor:request-log:v1`. Это описания запросов без подключения API.
[Формат, база сравнения и сценарии проверки](block-api-requests.md).
Первый ввод в начальный пустой блок даёт PUT, загрузка не создаёт операций.

Откройте DevTools → Console и фильтр `[note:blocks]`. После изменения текста,
типа или undo/redo и паузы saveDelayMs страница пишет JSON-строку с отступами.
При уходе ожидающий снимок также выводится сразу. Старые записи остаются
снимками прошлого состояния. При одном перемещении курсора записи нет.
Начальный mount не создаёт запись. Сам TextEditor не логирует без callback.
Сохранение локальное, без файлов, базы и сети.

Эти сценарии предназначены для пользователя; агент их в браузере не выполнял:

- [ ] Ввести русский текст и emoji: в массиве один paragraph с правильным content.
- [ ] Нажать Enter в начале, середине и конце: старый ID у первого фрагмента,
      новый у второго, все ID различны; повторить для H1–H3 и пустого блока.
- [ ] Переключить paragraph → H1 → H2 → H3 → paragraph: ID остается тем же.
- [ ] Выделить несколько блоков и сменить тип: каждый сохраняет свой ID.
- [ ] Ввести `# `, `## `, `### `: тип меняется на heading без смены ID.
- [ ] Скопировать/вставить блок: копия получает новый ID.
- [ ] Объединить блоки Backspace/Delete: сохраненный блок удерживает свой ID.
- [ ] Выполнить undo/redo после split, удаления и смены типа: проверить текст,
      порядок и восстановление ID без дубликатов.
- [ ] Переместить курсор без ввода: новой записи нет, ожидающий таймер не сбрасывается.
- [ ] Печатать непрерывно: логов и записей нет; после паузы в секунду один последний снимок.
- [ ] После паузы обновить страницу: текст, типы и ID восстановлены.
- [ ] Обновить страницу до паузы или скрыть вкладку: последнее изменение сохранено сразу.
- [ ] Удалить весь текст, дождаться паузы, обновить: старый текст не возвращается.
- [ ] Изменить NOTE_SAVE_DELAY_MS на 2000: ждать две секунды; при 0 передавать сразу.

Unit-тесты покрывают наши преобразования, проверки и адаптеры на заглушках,
без создания Tiptap Editor. Успешные CLI-проверки не подтверждают UI-сценарии выше.
