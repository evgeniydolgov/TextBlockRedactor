# Proposal

## Why

Существующий file-блок остаётся заготовкой: файл нельзя выбрать или скачать, а модель заметки принимает только пустые `url` и `name`. Нужен минимальный путь от выбора файла до сохранения его ID в заметке и последующего скачивания, не зависящий от конкретного файлового сервиса.

## What Changes

- Активировать выбор файла любого типа внутри пустого file-блока и добавить локальные состояния загрузки, ошибки и повторной попытки.
- Ввести необязательный адаптер файлов для загрузки `File` и получения URL либо Blob по ID; после загрузки сохранять только ID в `file.props.url` и имя в `file.props.name`.
- Показывать имя и кнопку «Скачать» в заполненном блоке; получать содержимое только по нажатию.
- Провести непустые `url`/`name` через валидацию, преобразования, `onChange` и существующее сохранение без изменения ID и порядка блоков; защитить асинхронную загрузку от удаления блока.
- Подключить на странице демонстрационный адаптер `Map<ID, Blob>` с ID через `createId`; после реализации обновить `humanNavigation.md`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `text-editor`: file-блок получает независимую загрузку и скачивание по сохранённому ID при сохранении текущего поведения редактора.

## Impact

Затрагиваются публичные пропсы `TextEditor`, file-узел и его команды, модель `NoteDocument` и преобразования Tiptap, страница с локальным адаптером, адресные unit-тесты и `humanNavigation.md`. `imageStorage` и поведение image-блока остаются прежними. Новые зависимости не нужны. Настоящий файловый сервис, backend, постоянное хранение бинарных данных, предпросмотр, внешняя проверка, drag-and-drop и вставка из буфера не входят в изменение.
