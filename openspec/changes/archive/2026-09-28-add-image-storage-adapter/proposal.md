# Proposal

## Why

Заготовка image сейчас не умеет выбрать файл, сохранить ссылку на него или показать уже загруженное изображение. Редактору нужен минимальный контракт хранилища, который позволит разработать этот цикл без зависимости от отсутствующего сейчас fileService и позднее подключить любой реальный сервис без изменения редактора.

## What Changes

- Добавить необязательный `ImageStorageAdapter` с отдельными операциями загрузки локального файла и получения изображения по сохранённому ID; конкретный SDK или fileService редактор не импортирует.
- Активировать выбор файла в image-блоке, показывать временные состояния загрузки и ошибки, а после успеха сохранять ID и имя файла в том же блоке одной отменяемой транзакцией.
- Разрешить заполненные строковые `url`, `name` и `caption` у image-блока и сохранять их через Tiptap, `onChange` и localStorage; `url` трактуется как непрозрачный ID хранилища.
- Получать и отображать существующий image-блок с заполненным `url` через адаптер, принимая готовый URL или Blob и освобождая созданные object URL.
- Добавить сменяемую демонстрационную реализацию адаптера в памяти для текущего приложения; Blob живут только до перезагрузки страницы и не записываются в localStorage.
- Оставить file-блок заготовкой. Не добавлять проверку статуса, alert-блоки, backend, IndexedDB, импорт внешних URL, удаление файлов из хранилища и редактирование метаданных.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `text-editor`: image-блок получает независимую загрузку, сохранение файловой ссылки и базовое отображение через внедряемый адаптер хранилища.

## Impact

- Публичные props редактора и конфигурация image-расширения Tiptap.
- Модель `NoteDocument`, валидация, преобразования Tiptap и существующий цикл сохранения/диагностических запросов.
- NodeView image-блока, его локальные асинхронные состояния и стили; file NodeView сохраняет прежнее поведение.
- Страница документа получает локальный адаптер в памяти. Новые пакеты и сетевые интеграции не требуются.
