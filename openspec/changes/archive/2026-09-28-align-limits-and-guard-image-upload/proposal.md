# Proposal

## Why

Спецификация лимитов описывает отбрасывание всего хвоста заметки после исчерпания текстового бюджета, хотя редактор сохраняет следующие подряд image/file при наличии мест для блоков. Кроме того, поздний ответ загрузки изображения сейчас может записать файловый ID в другой image-блок, если тот занял позицию исходного блока.

## What Changes

- Уточнить требование нормализации начальной заметки и его сценарии в соответствии с действующим алгоритмом. Код расчёта лимитов не менять.
- Записывать результат загрузки изображения только в исходный пустой image-блок с тем же ID. Поздний ответ после удаления, замены или заполнения исходного блока игнорировать.
- Добавить адресные unit-тесты защиты исходного блока и сохранения обычного успешного обновления.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `note-content-limits`: уточнить требование об обрезке начальной заметки при исчерпании текстового бюджета и наличии следующих подряд вложений.
- `text-editor`: уточнить жизненный цикл загрузки изображения для позднего ответа, когда исходный блок больше нельзя обновлять.

## Impact

Затрагиваются основные спецификации при последующей синхронизации, команда записи метаданных image-блока, её вызов из image NodeView и локальные unit-тесты. Публичный API `TextEditor`, формат `NoteDocument`, файловый адаптер, сохранение, preview запросов и зависимости остаются прежними. Вне задачи — изменение алгоритма лимитов, загрузки file-блока, интерфейса и общего устройства вложений.
