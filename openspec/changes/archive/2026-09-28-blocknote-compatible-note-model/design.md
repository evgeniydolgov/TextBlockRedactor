# Design

## Context

Мотивация и границы — в proposal.md. `document.ts` сейчас экспортирует TextEditorProps с JSONContent и общий emptyDocument. `createEditorOptions` передает JSON напрямую в useEditor и onChange. Страница рендерит TextEditor без callback. Расширения ограничены Document/Paragraph/Text/Heading/UndoRedo; ID отсутствуют. Vitest уже проверяет адаптеры блоков и опции в Node. Рабочее дерево перед proposal чистое.

Пользователь подтвердил блочный API и консольный вывод одновременно. Действующая спецификация Editor integration меняется явно, а текстовые операции и внешний интерфейс сохраняются.

## Goals / Non-Goals

**Goals:** отделить модель заметки от Tiptap, точно соблюдать форму BlockNote для текущего подмножества, сохранять идентичность блоков и сделать результат доступным в консоли.

**Non-Goals:** полноценный импорт произвольного документа BlockNote, вложенность, новые типы/стили, controlled React state, отдельный Editor на блок, хранение данных, UI-тесты. «Совместимость» относится к формату поддерживаемых данных, а не ко всем возможностям библиотеки.

## Decisions

### 1. Модель заметки и точная граница совместимости

Определить локальный discriminated union NoteBlock (paragraph | heading) и NoteDocument = NoteBlock[]. Формат сверяется с официальными [структурой](https://www.blocknotejs.org/docs/foundations/document-structure), [общими props](https://www.blocknotejs.org/docs/features/blocks) и [типографикой](https://www.blocknotejs.org/docs/features/blocks/typography), прочитанными 2026-09-23. Не объявлять собственный формат «приблизительно похожим» и не добавлять в выход внутренние поля Tiptap.

На этом этапе common props имеют значения default/default/left, heading дополнительно level: 1 | 2 | 3 и isToggleable: false. children всегда [], inline content — только text со styles: {}. Форма соответствует BlockNote, поддерживаемое множество значений намеренно ограничено существующими возможностями. Не устанавливать BlockNote ради типов: это добавит ненужную зависимость и не реализует конвертацию.

Пример полного выходного блока:

```json
{
  "id": "example-heading-id",
  "type": "heading",
  "props": {
    "backgroundColor": "default",
    "textColor": "default",
    "textAlignment": "left",
    "level": 2,
    "isToggleable": false
  },
  "content": [{ "type": "text", "text": "Заголовок", "styles": {} }],
  "children": []
}
```

Принимать полные блоки этого подмножества, не PartialBlock и не строковые сокращения BlockNote. Проверять вход маленькой собственной функцией без новой validation-библиотеки: поля/значения, уникальность ID, типы inline content, пустые styles/children. Ошибка сообщает индекс блока и поле. Неподдерживаемые данные отклонять, а не терять. Пустой массив и отсутствие initialContent — единственные специальные входы, создающие один пустой блок.

### 2. Два чистых преобразования

`blocksToTiptap` переводит массив в doc с paragraph/heading; ID записывается в attrs.id, level — в attrs.level. `tiptapToBlocks` читает тот же ID и создает новые plain objects со всеми полями публичного формата. Преобразование не генерирует ID и не мутирует вход. Для отсутствующего/дублирующегося ID или неподдерживаемого внутреннего узла выдавать диагностическую ошибку, не скрывать нарушение модели.

Текстовые сегменты без стилей объединять в один элемент text, пустой текст — в content: []; сохранять Unicode, пробелы и границы верхнеуровневых блоков. `blocksToTiptap` не создает пустые text-узлы. Round trip проверяется по нормализованному представлению, поскольку несколько соседних сегментов одного стиля эквивалентны одному.

Альтернативы: экспорт без смены API не выполняет подтвержденный переход; замена редактора на BlockNote расширяет задачу. Tiptap остается единственным изменяемым документом в памяти, массив — формат входа и снимок выхода.

### 3. ID живут в документе

Добавить OSS `@tiptap/extension-unique-id` версии, совместимой с установленной линейкой Tiptap; проверить MIT-лицензию и peerDependencies при apply. Настроить types: ['paragraph', 'heading'], attributeName: 'id'. Расширение отвечает за новые ID при split/paste и работу с историей; [официальная документация](https://tiptap.dev/docs/editor/extensions/functionality/uniqueid).

Начальный пустой документ создавать фабрикой с crypto.randomUUID (инъекция генератора в unit-тестах), а не модульной константой с общим ID. В hook создавать начальные опции один раз на экземпляр редактора, не генерировать новые ID при каждом React-render. initialContent остается начальным значением, без повторного setContent при изменении props.

Сохранение ID при paragraph ↔ heading — обязательный контракт. При apply проверить установленную реализацию команд и UniqueID: если смена типа не переносит attrs.id, добавить минимальный общий адаптер команд для переноса ID в той же транзакции. Не исправлять ID постфактум в сериализаторе и не строить индекс по позиции/тексту. Существующие unit-тесты команд расширить проверкой переноса ID на заглушках.

Пользователь отдельно подтвердил: при split исходный ID всегда остается первому фрагменту, включая пустой. UniqueID 3.31.3 сам переносит ID вправо при Enter в начале; поэтому добавить адаптер команды splitBlock, который после стандартного split в той же транзакции назначает старый ID первому фрагменту и новый второму до обработки UniqueID. Unit-тестировать этот адаптер на заглушках транзакции. Также сохранить ID в setNode/clearNodes и heading input rule; это покрывает панель, сочетания клавиш и ввод `# ` без реализации собственного редактора.

### 4. События и console.log

`createEditorOptions` принимает блочные props; onUpdate конвертирует getJSON и вызывает onChange, если он передан. Сохраняется отсутствие сериализации без callback. Callback вызывается для изменений документа, не для изменения selection; начальный mount сам по себе не требует вывода.

Страница передает `logNoteBlocks` в onChange. Этот небольшой обработчик выполняет `console.log('[note:blocks]', JSON.stringify(blocks, null, 2))`: строка фиксирует снимок и удобна для копирования. Лог не прятать за dev-only условием — запрос относится к текущей странице. Сам TextEditor не логирует, что сохраняет возможность переиспользования. Не добавлять дебаунс, панель JSON или запись в localStorage.

### 5. Файлы и unit-тесты

Ориентир 100–150 строк на файл, без искусственного дробления простых функций:

- `model/noteBlock.ts`, `model/createEmptyNote.ts`, `model/validateNote.ts` — модель, начальное значение и проверка границы.
- `model/blocksToTiptap.ts`, `model/tiptapToBlocks.ts` — преобразования.
- `model/document.ts`, `model/editorOptions.ts`, `hooks/useTextEditor.ts` — публичные props и подключение.
- `pages/document/logNoteBlocks.ts` — консольный обработчик страницы.
- Colocated `*.test.ts`, при необходимости общие fixtures/helper; список coverage расширяется на новые собственные функции.

Отдельные unit-задачи: factory/validation, обе конвертации и round trip, options/callback, сохранение ID в наших командах, logger. Vitest Node, без DOM, экземпляра Editor, snapshot и тестирования внутреннего алгоритма UniqueID. Стабильность ID чистого адаптера проверяется повторным экспортом и фиксированными последовательностями JSON с редактированием/сменой типа.

Живые Enter/paste/merge/undo сценарии передаются пользователю как ручные проверки, а не объявляются подтвержденными unit-тестами. Проверка установленного исходного кода расширения и типов снижает риск интеграции, но не заменяет браузерную проверку; агент браузер не запускает.

## Risks / Trade-offs

- Изменение BlockNote в будущем → фиксировать ссылки и дату контракта; не обещать поддержку произвольной будущей схемы.
- Полная форма не означает полный импорт BlockNote → явное ограничение подмножества, диагностические ошибки вместо потери данных.
- ID при смене типа/истории → хранить в attrs, проверить собственную передачу атрибутов; описать ручные сценарии.
- Частый console.log → допустим для запрошенного этапа диагностики; функция локализована на странице для последующего удаления.
- Новые функции выпадут из узкого coverage.include → обновить список и проверить наличие каждого нового модуля в отчете.

## Migration Plan

Сначала модель и чистые преобразования с тестами, затем ID и подключение нового API, после — logger и документация. Обновить README, контекст OpenSpec и формулировки API в conventions; старые завершенные changes не переписывать. Не завершать соседний modularize-text-editor в рамках этой задачи.

Миграции данных нет: приложение ничего не сохраняет. Существующие примеры initialContent/onChange и тесты переходят на массивы; не поддерживать два конкурирующих формата API. Откат возвращает прежний API и убирает новую зависимость и адаптеры, не затрагивая прочие пользовательские изменения. Коммит выполняет пользователь.
