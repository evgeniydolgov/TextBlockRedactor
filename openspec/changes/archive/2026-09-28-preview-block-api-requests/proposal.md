# Proposal

## Why

Редактор уже выдаёт NoteDocument после паузы и сохраняет его локально. Нужно
проверять, какие запросы к существующему блочному API соответствуют изменениям,
не подключая сеть и не смешивая транспортный контракт с редактором.

## What Changes

- Сравнение блоков по ID и содержимому между начальным/последним обработанным
  снимком и текущим; вывод только итоговых CREATE, UPDATE и DELETE.
- Описания запросов `{ method, path, body? }` в консоли под `[note:requests]`.
- Последний цикл сохранения под отдельным ключом localStorage
  `text-block-redactor:request-log:v1`: запросы, полный документ для записи и её
  результат. Каждый цикл заменяет предыдущий; без истории и временных меток.
- Одиночные операции и групповые CREATE/DELETE по предоставленному контракту.
- `before` — предыдущий ID, `after` — следующий; отсутствующий сосед равен null.
  Для последовательной группы позиция задаёт внешних соседей, порядок массива сохраняется.
- Общая точка запуска с действующим autosave: после saveDelayMs и при flush ухода.
  Сохранение localStorage, сообщения об ошибках и лог `[note:blocks]` остаются.
- noteId принимается извне и включается только в разрешённые контрактом поля;
  получение/создание заметки не добавляется.
- Вне задачи: HTTP-клиент, backend, ответы сервера, подтверждения/повторы запросов,
  Drag and Drop, операции перестановки, новые типы блоков и зависимости BlockNote.

## Capabilities

### New Capabilities

- `block-request-preview`: построение и локальный просмотр описаний запросов
  для изменений поддерживаемых блоков, включая управление базой сравнения.

### Modified Capabilities

Нет. Существующее поведение редактора и autosave сохраняется; добавляется отдельный
выходной адаптер. Основная text-editor спецификация пока отстаёт от реализованных
изменений blocknote-compatible-note-model, use-uuid-v7-block-ids и debounce-local-note-save.
Это предложение опирается на их фактический код и delta, не переписывая их требования.

## Impact

Новые маленькие модули под src/blocks/requests для типов, сравнения, построения
запросов и сессии preview. Интеграция с DocumentPage и createNoteSaveHandler,
отдельные logger и адаптер записи последнего цикла, unit-тесты Vitest и документация.
NoteDocument, UUID v7, Tiptap и формат основной записи заметки не меняются;
добавляется отдельная диагностическая запись. Код приложения в propose не изменяется.
