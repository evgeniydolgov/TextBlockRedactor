# Design

## Context

Мотивация и границы — в [proposal.md](proposal.md). В acceptance.md сейчас
обязательны полный build/lint/test/coverage и spec:validate; README процесса
и conventions.md также предписывают широкие проверки. Шаблон задач не требует
заранее ограничивать их область. Нужна согласованная правка этих документов.

## Goals / Non-Goals

**Goals:** единая политика экономной проверки, применимая к propose/apply/archive.
**Non-Goals:** новые инструменты контроля ресурсов, скрипт quality gate,
изменение тестовой инфраструктуры, аудит кода и старых changes.

## Decisions

### Одна политика, ссылки из рабочих документов

В AGENTS.md закрепить запреты, scope и остановку при росте контекста.
В acceptance.md разделить локальные критерии готовности и явно разрешённый full gate.
README процесса, conventions.md, task-template.md и контекст OpenSpec согласовать
с этой политикой. В корневом README пометить глобальные команды как доступные
по запросу, а не обязательные действия агента. Одного дополнения в AGENTS.md
недостаточно: иначе останутся противоречащие обязательные чек-листы.

### Минимальные проверки обычной задачи

В плане указывать затронутые модули, конкретные test-файлы, команды и причину выбора.
Для новой/изменённой логики запускать только относящиеся к ней unit-тесты.
Например: `npm.cmd test -- src/editor/limits/core/tests/fitInsertion.test.ts`.
Type-check использовать лишь когда его можно корректно ограничить затронутым кодом.
Если это невозможно штатными средствами, указать ограничение в отчёте; не подменять
локальную проверку полным tsc/build и не создавать ради неё новую инфраструктуру.
Для документации достаточно прочитать изменённые фрагменты и проверить их
согласованность и локальные ссылки. Не запускать тесты кода ради Markdown.

После успешной достаточной проверки остановиться. Повторный локальный запуск
оправдан исправлением или новой правкой, влияющей на уже проверенный результат.
Не добавлять «страховочные» проверки или полный gate в acceptance каждой задачи.

### Full Quality Gate — отдельное разрешение

Только явная команда пользователя, например `Run full quality gate`, разрешает
полный suite, coverage, lint, type-check, production build, OpenSpec validation,
diff-check и другие предусмотренные глобальные проверки. Обычные propose/apply,
archive и просьба закончить задачу таким разрешением не являются.
Статус OpenSpec и чтение diff — служебное чтение; это не запуск validation/diff-check.
В этом change автоматическую OpenSpec validation и diff-check не запускать.
Браузер/E2E/визуальные проверки требуют отдельного прямого запроса.
Разрешение gate не разрешает исправлять найденные посторонние проблемы.

### Scope и контекст

Исследовать только то, что необходимо для acceptance текущего change.
Постороннюю проблему кратко записать в отчёте и продолжить текущую работу.
Не исследовать её причины, предупреждения, улучшения архитектуры и дополнительные
edge cases без разрешения. Не перечитывать изученные файлы без конкретной причины
(например, файл изменён пользователем); использовать нужные фрагменты и краткие выводы.
При существенном росте контекста или необходимости прочитать много дополнительных
файлов остановиться, сообщить причину и требуемое исследование, дождаться ответа.
Не устанавливать выдуманные числовые лимиты токенов или файлов.

## Risks / Trade-offs

- Локальные проверки не подтверждают состояние всего проекта → честно указывать
  выполненный scope; полный gate доступен по отдельной команде.
- Старые планы могут требовать полные проверки → текущая явная политика пользователя
  имеет приоритет; невыполненные глобальные проверки не объявлять пройденными.
  Старые артефакты массово не переписывать.
- Инструкции процесса не являются техническим запретом CLI → применять их как
  правила агента без изменений npm scripts и установленных навыков.

## Migration Plan

Согласованно обновить только перечисленные документы, проверить изменённые пункты
и ссылки чтением. Не менять существующие незакоммиченные правки вне этого change.
Коммит и изменение индекса остаются ручными действиями пользователя.
