# Design

## Context

Мотивация описана в `proposal.md`. Проект использует React, TypeScript, Vite и Tiptap OSS; тестового runner и тестовых scripts сейчас нет. Собственные функции находятся в `paragraph.ts`, `headings.ts`, inline selector в `EditorToolbar.tsx` и настройке `useTextEditor.ts`. Остальные компоненты преимущественно собирают интерфейс.

## Goals / Non-Goals

**Goals:** проверять реальные production-функции в Node, сохраняя API `initialContent` / `onChange`, порядок определения блока и семантику команд. Тесты размещать рядом с кодом; ориентир размера файлов — 100–150 строк.

**Non-Goals:** создание экземпляра Tiptap Editor, React-рендеринг, DOM, UI, screenshots, snapshots, проверка схемы и алгоритмов сторонних пакетов. Не завершать соседний change по модульности и не менять CSS.

## Decisions

### Vitest вместо Jest

Vitest использует инфраструктуру Vite и поддерживает TypeScript, что соответствует текущему стеку. Jest тоже подходит для unit-тестов, но потребует отдельной настройки трансформации TypeScript/ESM без выигрыша для этого проекта.

Добавить `vitest` и `@vitest/coverage-v8` согласованных версий в devDependencies, проверив их совместимость с установленными Node и Vite при установке. Источники: [Vitest guide](https://vitest.dev/guide/), [Jest TypeScript setup](https://jestjs.io/docs/getting-started#using-typescript).

### Изолированная конфигурация

Создать `vitest.config.ts` с `environment: 'node'`, `globals: false` и поиском `src/**/*.test.ts`. Не объединять конфигурацию с dev-server Vite, у которого включено автоматическое открытие браузера. Импортировать API тестов явно; jsdom, browser mode и Testing Library не нужны.

Команды: `test` → `vitest run`, `test:watch` → `vitest`, `test:coverage` → `vitest run --coverage`. Однократный запуск должен завершаться самостоятельно. TypeScript проверяется отдельной существующей сборкой; включить новую конфигурацию в соответствующий tsconfig, если нужно.

### Минимальное выделение существующих функций

- `blocks/getActiveBlock.ts`: извлечь inline selector в функцию, принимающую редактор или null/undefined. Toolbar вызывает эту функцию через существующий `useEditorState`. Сохранить поиск первого активного блока в `editorBlocks` и fallback `paragraph`.
- `model/editorOptions.ts`: выделить `createEditorOptions(props)`, возвращающую собственные `content`, `editorProps`, `onUpdate`. Hook передает эти опции в `useEditor` и отдельно добавляет существующие extensions. Фабрика использует только type-imports Tiptap и текущий `emptyDocument`; импорт runtime расширений в unit-тесты не попадает.
- Не выделять классы, сервисы или универсальные abstractions ради тестов. Альтернатива — мокать React-hook и Tiptap модули целиком — сильнее связывает тесты с чужой реализацией.

### Матрица проверок

| Область | Проверяемый контракт |
| --- | --- |
| Paragraph apply | Цепочка focus → setParagraph → run; результат run возвращается и для true, и для false; heading-команда не вызывается |
| H1–H3 apply | Для каждого определения вызывается focus → setHeading с правильным level → run; результат возвращается, paragraph-команда не вызывается |
| isActive | Paragraph и каждый heading передают правильное имя/атрибуты, возвращают true/false от границы редактора |
| Выбор блока | Null/undefined и отсутствие совпадения дают paragraph; каждый активный блок дает свой id; при нескольких совпадениях сохраняется первое по порядку registry |
| Начальный документ | Отсутствие initialContent дает emptyDocument; переданный JSON используется без подмены и мутации |
| onUpdate | При callback JSON от getJSON передается один раз в onChange; без callback обработчик не падает и не вызывает getJSON, сохраняя optional chaining |

Для команд применять небольшие spies/stubs только используемых методов. Если тип Editor требует приведения, локализовать его в тестовом helper, не ослаблять production-типы и не использовать распространенный `any`. Заглушка не реализует редактирование документа: тест проверяет наш выбор команды и ее аргументы, а не результат работы Tiptap.

Проверки выполняются на экспортированных production-функциях, которые реально вызываются приложением. Не копировать алгоритм selector или onUpdate в тесты. Не писать отдельные тесты на JSX, type declarations, массивы констант или прямое подключение extensions.

### Покрытие и документация

V8 coverage включать явно для `paragraph.ts`, `headings.ts`, `getActiveBlock.ts`, `editorOptions.ts`, включая файлы, которые тесты могли не импортировать. Отчеты `text` и `json-summary`, без запуска браузера; generated coverage исключить из Git. Цель — покрыть ветви матрицы, без искусственного глобального порога для всего UI-приложения.

В README описать команды и границы покрытия; в `docs/agents/acceptance.md` добавить CLI unit-проверку для изменений нашей логики. Не выдавать процент этих функций за покрытие всего приложения.

## Risks / Trade-offs

- Заглушки не подтверждают совместимость реального Tiptap → явно ограничить выводы тестов; сохранить типизацию и выполнить build. Интеграционные тесты вне задачи.
- Выделение опций может случайно изменить defaults/callback → сохранить сигнатуру hook и проверять отсутствие/наличие props, не добавлять новую обработку данных.
- Пересечение с незавершенным `modularize-text-editor` → перед apply перечитать hook/toolbar, сохранить актуальные изменения; не расширять рефакторинг.
- Малый объем собственной логики → ограничить тесты контрактами матрицы; не увеличивать число тестов проверками стороннего пакета.

## Migration Plan

Добавить devDependencies и scripts, выделить функции без изменения поведения, затем добавить unit-тесты и документацию. Проверить test, coverage, build, lint и OpenSpec validate через CLI. Не запускать браузер или dev-server. Данные и runtime API не мигрируют; откат ограничен тестовой инфраструктурой и извлечением функций, без затрагивания чужих изменений. Коммит выполняет пользователь вручную.
