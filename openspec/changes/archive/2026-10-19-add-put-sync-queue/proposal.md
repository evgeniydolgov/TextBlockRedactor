# Proposal

## Why

Текущий preview описывает PUT для изменённых блоков, но не отправляет их и продвигает базу сравнения без подтверждения сервера. Для будущего подключения сервиса нужна очередь, которая сохраняет порядок PUT одного блока, не задерживает ввод и восстанавливает неподтверждённые изменения после обычного закрытия страницы.

## What Changes

- Добавить необязательный асинхронный адаптер `putBlock(block)` и очередь обновлений только для существующих подтверждённых блоков. PUT разных ID могут выполняться параллельно с общим пределом; для одного ID запросы идут строго последовательно, а промежуточные версии объединяются в последнюю.
- Разделить локальный черновик, базу диагностического preview и подтверждённое адаптером состояние. Последнее продвигается только после успешного ответа; неподтверждённые правки и сведения для их восстановления сохраняются локально.
- Показать отдельно локальное сохранение, синхронизацию и ошибку. После ошибки или таймаута остановить отправку для данного ID без автоматического повтора; добавить демонстрационный управляемый адаптер без HTTP.
- Сохранить существующий preview CREATE/DELETE без их реальной отправки. Неподтверждённые создания и удаления препятствуют сообщению о полной синхронизации заметки.

## Capabilities

### New Capabilities

- `block-put-sync`: очередь PUT, подтверждения, восстановление неподтверждённых правок и статус синхронизации существующих блоков.

### Modified Capabilities

- `text-editor`: уточнить, что локальное сохранение работает независимо от необязательного адаптера PUT, а отсутствие сетевых запросов относится к режиму без него.

## Impact

Затрагиваются интеграция страницы с `onChange`, отдельное локальное состояние очереди, обработка ошибок хранения и UI-статус; `NoteDocument`, ID блоков и диагностический формат `[note:requests]` остаются прежними. Настоящий backend, HTTP-клиент, версионирование, несколько устройств или вкладок и реальная отправка CREATE/DELETE не входят в change. Запрос с неизвестным исходом после перезагрузки не повторяется автоматически: правки остаются локально до будущего механизма выяснения исхода. Сохранность нельзя обещать при отказе локального хранилища или когда пользователь не вернётся к локально сохранённым, но не отправленным правкам.
