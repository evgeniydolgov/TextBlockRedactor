# Proposal

## Why

Сейчас каждое изменение заметки немедленно выводится в консоль, а перезагрузка
страницы теряет текст. Нужно сохранять заметку локально после паузы во вводе,
оставив время ожидания доступным для настройки снаружи редактора.

## What Changes

- **BREAKING**: `onChange` передаёт последнее состояние после паузы в изменениях,
  а не на каждый ввод. Новый проп `saveDelayMs` задаёт задержку в миллисекундах,
  по умолчанию 1000; каждое изменение перезапускает ожидание.
- Страница сохраняет массив блоков в localStorage и восстанавливает его при открытии.
- При уходе со страницы ожидающие изменения сохраняются сразу, по решению пользователя.
- Вывод `[note:blocks]` сохраняется, но происходит вместе с отложенной передачей блоков.
- Ошибки чтения/записи не ломают редактирование; интерфейс не сообщает об успешном
  сохранении, если запись не удалась.
- Вне задачи: backend, сеть, облако, список заметок, синхронизация вкладок,
  миграция ID, новые типы блоков и история undo/redo между перезагрузками.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `text-editor`: настраиваемая задержка `onChange`, локальное сохранение и загрузка,
  немедленное сохранение при уходе, изменение момента вывода в консоль.

## Impact

Затрагиваются `TextEditorProps`, `useTextEditor`, адаптер обновлений, `DocumentPage`,
новые небольшие модули таймера и localStorage, unit-тесты и документация.
Новых зависимостей не требуется; формат NoteDocument и правила ID остаются прежними.

Основная спецификация пока содержит `In-memory draft` и старый JSON-контракт.
Реализованные, но не архивированные изменения `blocknote-compatible-note-model`
и `use-uuid-v7-block-ids` уже задают фактический контракт блоков и ID. Это предложение
опирается на него и заменяет требования об отсутствии сохранения; перед будущей
синхронизацией этой delta необходимо синхронизировать предыдущие delta в их порядке.
