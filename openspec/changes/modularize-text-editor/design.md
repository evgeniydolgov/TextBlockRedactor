# Design

## Context

См. proposal.md — Why. Уже существуют App.tsx (15 строк), TextEditor.tsx (63),
extensions.ts (11), editor.css (14 плотных строк), index.css (18).
App.css (184 строки) и src/assets/ остались от шаблона и не импортируются из src.
В package.json нет тестового раннера. Текущие требования описаны в
../../specs/text-editor/spec.md и должны сохраняться.

## Goals / Non-Goals

**Goals:** явные границы страницы, редактора, панели, описаний блоков и состояния;
небольшие читаемые модули; единая точка сборки TextEditor.

**Non-Goals:** новые пользовательские возможности, переезд на другую библиотеку,
глобальное хранилище состояния, NodeView-компоненты и система динамической регистрации.

## Decisions

### 1. Структура по ответственности

```text
src/
  main.tsx
  App.tsx
  index.css
  pages/
    document/
      DocumentPage.tsx
      document-page.css
  editor/
    TextEditor.tsx
    extensions.ts
    editor.css
    model/
      document.ts
    hooks/
      useTextEditor.ts
    blocks/
      types.ts
      paragraph.ts
      headings.ts
      index.ts
    toolbar/
      EditorToolbar.tsx
      toolbar.css
```

App подключает DocumentPage; страница отвечает за заголовок и footer.
TextEditor подключает хук, EditorToolbar, EditorContent и подсказку.
Не выделяем отдельные компоненты для статичного заголовка или одной подсказки:
самостоятельного поведения у них пока нет.

### 2. Описания блоков и общий компонент панели

BlockDefinition содержит стабильный id, label, ariaLabel, apply(editor) и
isActive(editor). Типы Editor и JSONContent импортируются как type.
paragraph.ts определяет кнопку «Текст» и setParagraph;
headings.ts экспортирует уровни [1, 2, 3] как типизированную константу и создаёт
описания H1/H2/H3 с setHeading({ level }). Команды сохраняют chain().focus().run().
blocks/index.ts собирает массив в порядке «Текст», H1, H2, H3.
extensions.ts использует ту же константу уровней для Heading.configure,
чтобы поддерживаемая схема и панель не расходились.

EditorToolbar принимает один Editor | null, рисует кнопки из определений и через
useEditorState вычисляет активный id. Подписка остаётся внутри панели, чтобы
выделение текста не требовало дублирования документа в React state.
При null все кнопки disabled, начальное выделение — «Текст», как сейчас.
Сохраняются доступные имена, role=group, aria-pressed и type=button.

Альтернатива — четыре почти одинаковых React-компонента кнопок — дублирует
разметку и обработку фокуса. Общая панель и отдельные определения блоков дают
необходимую инкапсуляцию. Содержимое документа по-прежнему рисует Tiptap.
Зависимости направлены от сборки к модулям; headings.ts не импортирует extensions.ts
или blocks/index.ts, циклические импорты не допускаются.

### 3. Жизненный цикл и публичный интерфейс

useTextEditor принимает существующие initialContent/onChange и вызывает useEditor.
В model/document.ts находятся тип TextEditorProps и начальный JSON с пустым абзацем.
TextEditor продолжает принимать те же props и доступен по прежнему пути импорта.
Не вводим эффекты setContent на каждый рендер: initialContent остаётся начальным
значением, onChange вызывается после изменения документа с editor.getJSON().
Сохраняем один экземпляр редактора, историю UndoRedo и атрибуты textbox.

### 4. Стили и размер файлов

index.css оставляет reset и базовую типографику; document-page.css — страницу,
toolbar.css — панель, editor.css — редактируемый документ и подсказку.
Существующие классы, значения, media queries и внешний вид сохраняются.
CSS форматируется с отдельной строкой на декларацию, без уплотнения ради счётчика.
Ориентир 100–150 физических строк применяется к TS/TSX/CSS исходникам,
включая комментарии и пустые строки. Это мягкая верхняя граница, а не минимум:
маленькие модули не дополняются искусственно; превышение 150 строк требует
обоснования и проверки возможности разделить обязанности. Автоматический лимитер
и новые линтеры не добавляются. Правило фиксируется в conventions.md.

## Risks / Trade-offs

- Потеря фокуса, неверная активная кнопка → браузерная проверка кликов,
  переключения курсора, клавиатурной навигации и aria-pressed.
- Пересоздание документа или сброс истории → проверить ввод, undo/redo,
  initialContent/onChange и ререндер родителя без изменения документа.
- Расхождение схемы и кнопок → одна константа уровней, проверка порядка и
  всех четырёх команд; новые уровни в этой задаче не добавляются.
- Изменение CSS при переносе → сравнить исходный вид и результат на широкой
  и узкой странице; значения стилей не менять.
- Больше файлов для маленького приложения → каждая папка имеет конкретную
  ответственность; общий каталог shared и лишние обёртки не вводятся.

## Migration Plan

Сначала выделить модель и определения блоков, затем хук и панель,
после этого собрать TextEditor и вынести страницу. Обновить стили и документацию.
Удалять только подтверждённо неиспользуемые файлы src/App.css и src/assets/;
проверить ссылки по всему проекту, включая HTML и CSS, перед удалением каждого.
Возможный откат — вернуть импорты и прежнюю композицию без миграции данных,
поскольку JSON-формат и пользовательское поведение не меняются.

Проверки: build, lint, строгая валидация OpenSpec, отсутствие циклов,
подсчёт строк и браузерная регрессия по text-editor. Отдельный тестовый фреймворк
в этой задаче не устанавливается. Проверку JSON-контракта выполнить через временный
локальный стенд компонента с initialContent/onChange и убрать стенд после проверки.
HTTP 200 и успешная сборка не заменяют проверку взаимодействия.
