# Proposal

## Why

Собственная логика редактора сейчас не защищена автоматическими тестами: ошибки в выборе блока, передаче команд или обработке изменения документа могут остаться незамеченными. Нужны быстрые unit-тесты без запуска браузера и проверки внутренней реализации Tiptap.

## What Changes

- Добавить Vitest и покрытие V8, отдельную конфигурацию с окружением Node и команды однократного запуска, наблюдения и покрытия.
- Проверить наши адаптеры команд «Текст», H1–H3 и определения активности блока на небольших заглушках интерфейса редактора.
- Выделить выбор активного блока из toolbar и формирование собственных опций редактора из hook в небольшие функции; проверить их без React-рендера и создания Tiptap Editor.
- Проверить начальный документ и передачу JSON в пользовательский onChange, сохранив текущее поведение.
- Описать запуск тестов, границы покрытия и критерии приемки в документации.
- Исключить UI, скриншоты, snapshots, браузер, внутреннюю логику Tiptap и самостоятельное создание коммитов.

## Capabilities

### New Capabilities

Нет: добавляется инфраструктура проверки собственного кода.

### Modified Capabilities

Нет: публичное поведение редактора и требования `text-editor` сохраняются. Для изменения задано `skip_specs: true`; delta specs не создаются.

## Impact

- `package.json`, lockfile, новая `vitest.config.ts`, при необходимости область проверки TypeScript для конфигурации.
- `src/editor/blocks/`, `src/editor/model/`, точечные изменения `EditorToolbar.tsx` и `useTextEditor.ts`, colocated файлы `*.test.ts`.
- README и критерии приемки агента.
- Только devDependencies; без сервисов, платных возможностей, runtime-зависимостей для тестирования или изменения CSS.
- Незавершенное `modularize-text-editor` затрагивает те же hook и toolbar: при реализации сохранить актуальные изменения и не выполнять его оставшиеся задачи в рамках этого change.
